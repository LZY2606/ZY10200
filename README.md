# 光回波事件室（OTDR Echo Event Room）

本地服务，用于光纤维护团队对不同**脉宽、群折射率、平均次数**的 OTDR 轨迹做
导入、距离校准、分段基线分析、事件识别与跨轨迹人工复核。技术栈：Go +
`net/http` + 服务端渲染 SVG + SQLite（`modernc.org/sqlite`，纯 Go，免 CGO）。

## 安装与演示

```bash
go mod download
go test ./... -count=1
go run ./cmd/server --listen 127.0.0.1:5540
```

浏览器访问 <http://127.0.0.1:5540>，页面标题为 **光回波事件室**。

参数：

- `--listen`：监听地址，默认 `127.0.0.1:5540`
- `--db`：SQLite 文件路径，默认 `otdrroom.db`

数据库为空时会自动导入内置固定夹具（fixture）。页面上“清空数据库并重新导入复核”
会调用 `Reset` 后重新播种，用于回归复核；也可用“导出运行记录 JSON”留档。

## 页面内容

- 每条轨迹一张四联 SVG：① 原始线性采样（截断后留空）② 对数功率 dB 与分段基线
  ③ 事件候选（事件窗 + 锚点）④ 累积事件损耗；顶部黄色阴影是发射端死区。
- 一张距离校准对齐图：两条轨迹共享米制横轴；实心圆为实事件、空心圆为幽灵候选；
  **只有人工显式确认的对应**才画绿色虚线。
- 操作：修改群折射率（重新校准并重算对齐）、调整发射端死区、确认跨轨迹事件对应、
  把某个峰在引用前导强反射的前提下判为幽灵候选、否决幽灵、导出/清空重导。

## 固定夹具（地面实况）

两条采集参数不同、但物理设施相同的轨迹，保证“采样索引 ≠ 物理距离身份”：

| 轨迹 | 脉宽 | 群折射率 n | 平均次数 | 采样间隔 | 样本数 |
|---|---|---|---|---|---|
| TR-A | 100 ns | 1.4680 | 16384 | 5.0 ns | 1600 |
| TR-B | 150 ns | 1.4650 | 8192  | 6.0 ns | 1400 |

物理事件（同一根光纤）：

- **300 m**：真实反射连接器（强反射峰 + 约 0.55 dB 插入损耗）
- **600 m**：由 300 m 强反射形成的**幽灵峰**（二次回波，距离比 ≈ 2，无台阶）
- **850 m**：低损耗熔接（约 0.45 dB 非反射台阶）
- **1500 m**：**轨迹截断**——之后无任何回波，只能声明已测长度**下界 ≥ 1500 m**，
  绝不伪造成光纤末端

夹具由确定性 LCG 噪声生成（见 `internal/otdr/fixture.go`），每次重新导入逐样本一致。

## 数据口径（关键不变量）

1. **原始采样不可变。** `samples.power` 存导入时的线性功率，任何参数修订都不改动它。
2. **采样索引才是样本/事件身份。** 事件锚定在 `anchor_index`；米制距离只是
   `d = c·t / n` 的换算属性。修改群折射率后重新调用分析，**锚点索引不变、距离刷新**。
3. **修订号 `param_rev`。** 每次改折射率/死区 `param_rev + 1`，解释快照按
   `(trace_id, rev)` 保存；用户判定与跨轨迹对应都锚定采样索引，跨修订继续有效。
4. **外观相近不自动等同设施。** 对齐图只负责画在同一米制坐标；跨轨迹对应必须由
   维护人员显式确认（`event_links`），系统不做距离近邻自动合并。
5. **幽灵判定必须给证据。** 不能只凭峰高：必须引用同轨迹更早的**前导强反射**
   （峰高阈值）且满足距离比 `d_ghost / d_parent ≈ 2`（容差 0.20，自动识别用 0.12）。
6. **重叠事件窗不重复计损。** 累计损耗先把事件窗取**并集**，再按并集窗两侧高原
   电平的净下降计一次；幽灵与截断窗不产生损耗。
7. **截断只报告长度下界。** 尾部连续零功率缺口判为截断，报 `lower_bound_m`，
   不报光纤末端；只有信号自然衰减进入噪声底才会判 `fiber_end`（夹具不使用）。

每次解释快照（`interpretations.payload`）都保留：所用折射率与死区、逐采样 dB、
逐采样分段基线、基线拐点、事件区间（锚点/窗/距离）、台阶损耗、峰高、幽灵父反射与
距离比证据、累计损耗与长度下界，以及所依据的 `rev`（证据轨迹版本）。

## 算法概览（`internal/otdr`）

- 距离校准：`SampleDistanceM` / `DistanceToSampleIndex`，时间基为仪器采样间隔。
- 反射峰：约 6 脉宽宽窗滚动中值得到无峰局部电平，正残差超阈值且簇宽达标成峰。
- 台阶（熔接）：约 2 脉宽窄中值，反射簇两侧按宽窗屏蔽以防拖尾伪造台阶；
  左右高原取在候选点 1 个脉宽之外，要求持续下降；台阶电平用斜率修正 + 截尾均值。
- 分段基线：事件窗之间做 MAD 稳健线性拟合（剔除反射尾正离群点），窗内线性桥接。
- 幽灵分类：引用前导强反射并校验 2 倍距离关系。
- 末端：零功率缺口 → 截断下界；自然沉入噪声底 → 光纤末端。

## 运行记录导出 / 复核

- `GET /runs/export` 下载完整 JSON：轨迹与原始采样、全部解释快照、用户判定、
  跨轨迹对应、操作日志（`run_log`）。
- `POST /reimport` 清空业务表后重新播种夹具；`internal/store` 的
  `ExportRun`/`ImportRun`/`Reset` 也支持导出文件的回放复核。
- 自动测试覆盖：四类事件识别、改折射率后采样身份不变、重叠窗不重复计损、
  截断只报下界、距离换算往返、存储修订/判定/对应幂等、HTTP 端到端操作。

## 目录

```
cmd/server          服务入口
internal/otdr       距离校准、夹具、基线、事件/幽灵/截断识别、累计损耗
internal/store      SQLite 迁移与仓储（轨迹/采样/解释/判定/对应/运行日志）
internal/app        编排：重算解释、判定叠加、对应管理、对齐视图、播种
internal/web        HTTP 处理器、SVG 渲染、操作页面
```
